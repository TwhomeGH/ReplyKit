# 主 App 日誌寫入政策

`AppLogPersister` 的檔案、緩衝與排程由單一 utility queue 管理。持有 handle 不等於持續 I/O。前景重用 handle；背景先嘗試 flush、同步與關閉，後續背景日誌每批寫完也關閉。依賴既有短背景窗口提供執行機會，無法保證系統終止前零遺失；不依靠 deinit 保存最後資料。

## 頻率與容量

- 有資料才排程，0.5 秒或 50 筆先到者寫入，沒有資料不安排週期寫入。
- 提前 flush 撤銷舊工作並以世代拒絕過期工作。日誌頁讀取不再強制 flush，顯示可能晚約一個批次。
- 寫入器緩衝上限 2 MiB，超出拒收尾端紀錄並帶外報告丟棄筆數；此上限不代表整個 App 日誌管線或尚未執行的 queue 工作容量上限。
- 寫入失敗先回復寫入前長度，成功回復才允許兩秒後重試，最多三次嘗試。回復失敗或耗盡次數，丟棄批次並帶外報告；跨程序外部修改同一檔案不在此回復保證內。
- 成功寫入才累加位元組與行數。作業系統接受 write 不代表磁碟永久保存成功；背景 synchronize 失敗另行診斷。

## 裁切與錯誤

超過約 7,000 行或 8 MiB 觸發裁切，最多讀取最後 4 MiB，再保留最多 5,000 行。容量邊界的部分首行排除，單行本身超過上限時可能無完整行可保留。先關寫入 handle，原子寫回保留資料，成功才更新索引及計數，下一批重新開檔。啟動校準分塊讀取。

I/O 錯誤使用 OSLog 與既有 Socket 帶外摘要，避免寫入失敗再次產生日誌回饋。App Group 合併必須主檔追加成功才清空來源；擴展與主 App 跨程序合併期間的競爭仍需另行協調，不能因為本次改動就視為解決。

診斷匯出最近一次 flush 失敗時報錯，不將空緩衝當成成功證明。歷史曾丟棄的資料無法由匯出還原。另見 LOG_DIAGNOSTIC_EXPORT.md。

## 驗收

已補尾端裁切的 UTF-8、行數、未換行與空資料回歸測試。Apple CI 與實機仍需確認：前背景快速切換、磁碟不足、部分寫入／回復失敗、重試耗盡、連續大量日誌、裁切後持續追加與日誌頁更新。Windows 語法檢查不等於上述測試通過。
